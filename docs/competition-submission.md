# OpenFix 参赛方案

## 项目定位

**项目名称：** OpenFix 工业设备检修证据链智能体

**参赛赛道：** 开源基础软件与解决方案

**项目类型：** 面向制造业设备维护场景的开源行业应用平台

**一句话介绍：** 把报警、SOP、历史工单和安全规程组织成可追溯的诊断证据链，让检修建议有依据、危险操作有拦截、正式执行有审批。

## 行业痛点

设备报警发生后，现场人员需要在很短时间内完成判断。实际工厂中，关键知识经常分布在设备手册、控制系统、老师傅经验和历史工单中：

- 手册内容长，报警代码定位慢。
- 历史工单缺少统一结构，难以复用。
- 通用 AI 容易给出无法验证甚至危险的维修建议。
- 小企业缺少知识平台团队，难以部署复杂 RAG 基础设施。

结果是重复排查、重复停机和不必要的备件更换，同时高风险操作也可能因为信息不完整而失控。

## 目标用户

- 中小制造企业的设备部与维修班组。
- 工厂动力站、加工线和包装线的高关键设备维护人员。
- 为制造企业提供设备运维服务的系统集成商。
- 建立行业设备知识库的开源社区与科研机构。

## 解决方案

OpenFix 提供一个本地优先的维护决策工作台：

1. 现场人员输入设备编号、报警代码和异常现象。
2. 系统联合检索 SOP、历史工单和设备结构。
3. 结构化规则确保报警码精确匹配，避免相近故障混入。
4. 确定性安全规则拦截烟火、压力、电气、高温、旋转部件等风险。
5. 系统输出故障假设、证据来源、信息缺口和建议步骤。
6. 普通诊断可转为待审批工单，批准或驳回均写入审计记录。

## 创新点

### 1. 证据与执行分离

系统只生成“诊断证据包”，不直接生成执行许可。正式执行需要授权人员批准，且高危条件下只输出安全处置与补充信息要求。

### 2. 报警码优先的结构化检索

中文 BM25 解决术语匹配，报警码和资产类型约束解决准确性。出现 E201 时，不会把同一空压机的 E203 工单作为等价证据。

### 3. 可测试的安全政策

安全规则由代码实现，可以在评测集中自动验证。安全门槛独立于检索分数和语言生成。

### 4. 现场可部署

无第三方 Python 依赖、无需云 API、无需向量数据库。Windows 附带便携运行时，也可使用 Docker 在边缘服务器运行。

### 5. 主动拒答

系统在证据不足时明确拒绝推断，提示需要补充设备、报警、量测数据和复位状态，不追求“每个问题都给答案”。

## 技术架构

```text
现场描述
  → 中英混合 token
  → SOP / 历史工单双 BM25 索引
  → 报警码与资产结构重排
  → 确定性安全规则
  → 证据包与证据链
  → 待审批工单
  → SQLite 审计轨迹
```

详细设计见 [ARCHITECTURE.md](../ARCHITECTURE.md)。

## 当前实现

- 6 台演示设备与 4 类高关键设备。
- 8 份 SOP / 安全规程。
- 7 条结构化历史工单。
- 12 条可复现评测任务。
- 响应式 Web 工作台。
- 工作台、工单、审批、驳回和审计完整闭环。
- 21 项后端单元测试。
- 浏览器端完整流程验证，桌面与 390px 移动端均无横向溢出。

## 与评审维度的对应

### 技术创新（30%）

- 报警码优先的结构化检索重排。
- 证据检索与安全政策分离的决策包络。
- 高危场景的确定性动作阻断。
- 可复现的主动拒答与安全门评测。

### 场景落地（30%）

- 从现场描述直接进入诊断和待审批工单。
- 本地运行、SQLite 持久化、无云依赖。
- 可对接 CMMS / EAM、设备手册和开源本地模型。
- 输出包含缺失信息，便于维修人员继续取证。

### 开源治理（20%）

- Apache-2.0 许可证。
- 贡献、治理和安全策略文档。
- 数据与代码分离，便于替换为企业自有知识库。
- 单元测试和评测脚本可复现。

### 长期发展（20%）

- 可扩展 PDF 解析、混合向量检索和传感器趋势。
- 通过 CMMS 工单回流形成企业知识闭环。
- 后续可在真实试点中衡量首轮定位时间、返工率和重复停机率。

## 演示脚本

### 场景一：正常诊断

输入：

```text
AC-01 空压机报 E201，排气温度高，复位后很快又停机
```

展示：

- 自动识别 AC-01。
- 命中 E201 SOP 与冷却器堵塞历史工单。
- 输出证据链、检查步骤和缺失信息。
- 转换为待审批工单并批准。

### 场景二：安全拦截

输入：

```text
空压机压力还在，要求直接拆油管检查
```

展示：

- 系统状态升级为“需要安全复核”。
- 引用通用能量隔离规程。
- 明确禁止带压拆管。
- 只给出停止、泄压、零能量验证等安全步骤。

### 场景三：主动拒答

输入：

```text
今天产量怎么样
```

展示系统拒绝生成维修结论，并要求补充设备与故障信息。

## 验证结果

当前随项目提供的合成评测集结果：

- 知识证据召回：100%
- 历史案例召回：100%
- 拒答准确率：100%

## 试点计划

建议选择一个动力站或关键加工设备班组开展 4 周试点：

1. 脱敏导入 100—300 份设备手册与历史工单。
2. 由维修主管审核 100 条真实故障描述。
3. 对比接入前后的首轮定位时间、重复停机率和工单返工率。
4. 记录安全规则误报、漏报和人工纠正原因。
5. 将已验证的工单回灌知识库，但保持版本和审核人信息。

## 风险与边界

- 演示数据为合成数据，尚未完成真实客户生产验证。
- 演示审批流程没有真实身份认证，生产环境必须接入企业 SSO。
- 高频风险不能只靠关键词规则，必须结合设备危险源清单与作业票。
- 接入大模型后，需要额外评估提示注入、越权检索和输出越界。

OpenFix 的安全原则是：**没有证据不诊断，没有审批不执行。**
