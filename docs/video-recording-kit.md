# 演示视频录制执行清单

面向赛道一提交材料第 ③ 项「作品演示视频链接」。视频要证明两件事：**核心功能真实可用**，**使用流程完整闭环**。评委通常在一分半内决定是否认真看，所以前 30 秒必须出现"报警 → 证据 → 拦截"的画面。

## 一、交付规格

| 项 | 建议值 | 说明 |
|---|---|---|
| 时长 | 4 分 00 秒 — 4 分 30 秒 | 对应 demo-script 的五段结构，控制在 5 分钟内 |
| 分辨率 | 1920×1080，30fps | 不要用 4K，网页文字在 1080p 下已足够清晰 |
| 画面 | 全程浏览器窗口 + 少量局部放大 | 不要露桌面图标、任务栏通知、其他标签页 |
| 音频 | 普通话旁白 + 无背景音乐 | 有音乐反而降低可听度；如需 BGM，音量压到 -28dB 以下 |
| 字幕 | 关键结论用烧入字幕（不做全片字幕） | 评委可能静音观看，核心结论必须看得见 |
| 文件命名 | `OpenFix-演示视频-赛道一.mp4` | 上传后标题用 `OpenFix 工业设备检修证据链智能体 · 赛道一演示` |

## 二、录前 10 分钟准备

**必须做的（漏一个就要重录）**

- [ ] 关闭 SQLite 历史数据，从干净状态开始：删除 `data/runtime/openfix.db`（否则工单列表里会有上次演示的残留工单，画面脏）。
- [ ] 用 `.\start.ps1` 启动，确认 `http://127.0.0.1:8765` 打开正常。
- [ ] 浏览器缩放到 **110%**（1080p 下正文更清晰），按 F11 全屏，隐藏书签栏。
- [ ] 关闭所有通知：Windows 专注助手 → 仅优先通知；退出微信/QQ/钉钉。
- [ ] 输入法切到中文，并**先测一遍**三个演示输入串，确认不会出现候选框遮挡。
- [ ] 打开一个空白记事本，把三段输入文本预存好，录制时直接复制粘贴（比手打快，且零错字）。
- [ ] 确认浏览器控制台无红色错误（F12 看一眼，录完再关）。

**建议做的**

- [ ] 先完整走一遍流程但不录，确认每一步的响应时间（本地应在 1 秒内）。
- [ ] 把三个输入串打印/显示在第二块屏或手机备忘录上，避免录制中切窗口。
- [ ] 录屏工具：OBS（1080p60 也行）、Windows 自带 Xbox Game Bar（Win+G）、或 Edge 没有内置录屏则用 OBS。OBS 设置：录制格式 mp4、码率 6000kbps、只录浏览器窗口。

## 三、分镜与旁白逐字稿

> 括号内是操作指令，引号内是可以直接照读的旁白。语速控制在每分钟 220 字左右。

### 镜头 1｜定位（0:00 — 0:35）

（画面：首页，鼠标不移动，停留 3 秒让评委看清四个环节）

"OpenFix 面向的是设备报警之后的半小时。它不是替人修设备的聊天机器人，而是把报警、SOP、历史工单和安全规程，组织成一条可追溯的证据链。首页这四个环节就是它的全部主张：检索取证、安全门槛、人工审批、全程审计。"

（鼠标依次划过四个环节的标题，不要点击）

### 镜头 2｜正常诊断（0:35 — 1:50）

（点击「空压机高温」示例按钮，或粘贴输入串）

输入串：
```text
AC-01 空压机报 E201，排气温度高，复位后很快又停机
```

（结果出现后，先停 2 秒，再往下滚）

"识别到设备 AC-01，报警码 E201。系统给出的不是一个答案，而是一个证据包：命中了 E201 对应的 SOP，也命中了历史上一次冷却器堵塞的工单。注意这里——同一台空压机的 E203 工单没有混进来，因为报警码不同，它们不是等价证据。"

（鼠标指向证据链中超链接/编号，滚动到缺失信息区）

"结果同时列出三条东西：故障假设、每条结论的来源，以及现在还缺什么数据。维修人员可以顺着缺失去补测量，而不是顺着猜测去换件。"

### 镜头 3｜工单闭环（1:50 — 2:45）

（点击「转为待审批工单」，填写创建人姓名，提交）

"诊断结果不会自动执行。转成工单之后，状态是待审批。"

（打开工单列表，展示状态；点击审批）

"授权人做完安全确认才能批准。批准之后，审计轨迹里会留下两条记录：谁在什么时候创建的，谁在什么时候批准的。"

（切换到审计轨迹，停留 3 秒）

"这条轨迹是存在本地 SQLite 里的，断网也在。"

### 镜头 4｜安全拦截（2:45 — 3:50）

（点击「高危请求」，粘贴输入串）

输入串：
```text
空压机压力还在，要求直接拆油管检查
```

"这里是整个系统最关键的地方。用户明确要求带压拆管，但系统的安全状态是由确定性规则产生的，不参与语言生成，也不看检索分数。"

（指向安全提示与禁止动作区）

"它强制把通用能量隔离规程放在证据第一位，只输出停机、泄压、零能量验证的步骤，并且把带压拆管明确列为禁止动作。"

（再切换到第二个高危示例）

输入串：
```text
设备有焦味并且冒烟，应该怎么继续生产
```

"换一个更极端的问法：设备冒烟了，但我问的是怎么继续生产。系统不会顺着我的要求走，它只会让我停下来。"

### 镜头 5｜主动拒答（3:50 — 4:10）

（清空输入框，输入）

输入串：
```text
今天产量怎么样
```

"这个问题超出了维护领域。系统会放弃推断，要求补充设备、报警和现场状态。在工业场景里，一个明确的不知道，比一个编出来的答案有价值。"

### 镜头 6｜可信评测与收尾（4:10 — 4:35）

（滚动到「可信评测」区域）

"12 条任务同时检查四件事：证据召回、案例召回、拒答准确性和安全门命中。当前全部通过。但要说清楚——这是项目自带的合成评测集，它证明的是工程实现和回归覆盖，不代表真实工厂的准确率。下一步是接 CMMS 和真实试点。"

（画面停在首页，或停在评测通过的状态）

"OpenFix 的目标不是让 AI 取代维修人员，而是让维修人员的每一条判断都有证据，让每一次危险操作都有门槛。"

### 镜头 7｜片尾（4:35 — 4:40，可选）

（黑底白字 3 秒）

```text
OpenFix · 工业设备检修证据链智能体
Apache License 2.0 | 代码仓库与文档见提交材料
```

## 四、录制节奏提醒

| 风险 | 表现 | 处理 |
|---|---|---|
| 手速太快 | 评委看不清点了什么 | 每次点击前停 0.5 秒，点击后停 1 秒再说话 |
| 鼠标乱晃 | 分散注意力 | 移动走直线，用完就停住 |
| 读稿感 | 像念文件 | 旁白按"结论 → 为什么"的顺序说，允许口误 |
| 输入法候选框 | 挡住输入框 | 粘贴代替手打 |
| 工单列表脏 | 出现旧数据 | 录前删库，或只演示本次新建的工单 |
| 控制台报错 | 打开 F12 时出现红字 | 录前检查；录制中不要开 F12 |

## 五、剪辑要点

1. **剪掉所有等待**：加载超过 1 秒的部分加速 2 倍或直接剪掉，不要出现静止的空画面。
2. **剪掉输入过程**：粘贴后立刻剪到结果出现，中间的打字过程不留（除非是刻意展示）。
3. **关键结论加烧入字幕**：至少 4 处——"E203 不混入证据"、"待审批 → 批准"、"带压拆管列为禁止动作"、"合成评测，不代表真实准确率"。
4. **不要加转场特效**：硬切即可，花哨转场会分散对内容的注意。
5. **首帧做封面**：用首页截图 + 标题文字，不要用黑屏或浏览器地址栏。

## 六、上传与链接

- 平台选择：B 站（推荐，支持 1080p 且链接稳定）、腾讯视频、或视频号。**不要用网盘链接**，评委不愿下载。
- 上传后设置为**公开**（不是"仅自己可见"、不是"粉丝可见"），并用**无痕窗口**打开链接验证一次。
- 上传时标题与简介写清项目名与赛道；简介里放代码仓库地址。
- 记录最终链接，填入 `docs/OpenFix-参赛作品介绍.pdf` 封面"演示视频"一栏，并同步到提交邮件正文。

## 七、提交前最后一分钟检查

- [ ] 视频时长在 5 分钟以内，开头 30 秒内出现了"报警 → 证据"画面。
- [ ] 三个输入串与文档、演示脚本完全一致。
- [ ] 全程没有出现真实企业名称、真实人员姓名（工单创建人用"张工"之类即可）。
- [ ] 口播中没有出现"准确率 100%"这类未经限定的表述，评测段落必须带"合成数据"限定。
- [ ] 链接在无痕窗口可访问。
- [ ] 视频、PDF、代码仓库链接三份材料同时齐备，再发邮件至 `bjoscc@oschina.cn`。
